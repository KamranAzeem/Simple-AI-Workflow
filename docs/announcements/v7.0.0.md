# v7.0.0

This major release replaces the three per-file state-file caps with one shared budget and adds a safe way to shrink long items.

- The three state files share a 30 KB (30,720 bytes) advisory budget. They trade space, and the report shows each file's bytes.
- An item line over 300 characters is condensed: the full item moves to today's daily checkpoint, and a short stub with every findability identifier stays behind.
- When a stub cannot keep both the 300-character cap and the identifiers, the item stays as it is and is reported as `not condensable`.
- The checkpoint condenses when needed, because it still has the session context. `"repair state files"` runs the same pipeline as a fallback.
- The load report shows bytes, the count over 300 characters, and the five longest lines by line number. It never quotes the line text.
- The header blocks no longer name per-file sizes. The progress header keeps the 14-day archive rule.
- One migration: after upgrading, run `"repair state files"` once in each project to refresh the header block. The load tells you when a header is out of date.
- Knowledge promotion stays with the checkpoint. The repair prints candidate lines and writes no Project Knowledge.

Upgrade: pull the clone, run the sync script, then run `"repair state files"` once in each project.
