# Simple-AI-Workflow v5.3.0

This release makes the state-file headers self-describing and verifiable. The rules now travel with the files, and a drifted header is caught at load instead of silently changing what the file is for.

## What changed

- Each state file and each new daily checkpoint starts with a canonical header block. The block is visible, names what belongs in the file, what does not, the size soft target, the single writer, and the repair trigger.
- `load context` compares the header with the common policy at boot. A mismatch is reported as degraded state-file health, with an instruction to run `repair state files`. The load remains read-only.
- `repair state files` restores the canonical header, normalizes the separator, fixes the daily title date, and preserves the body with a full-file backup and a checksum.
- The 8 KB, 7 KB, 5 KB, and 20 KB figures are soft targets. A file may exceed its target when live work needs the room; completed entries move to the diary first.
- Historical daily checkpoints are not backfilled. The rule applies to checkpoints written from this release onward.

## Why it matters

The header is the only rule set guaranteed to be present whenever the AI reads a state file. A pure comment can be skimmed; a visible block with the rules cannot. A wrong header used to pass every check because only its presence was tested. Now the text is canonical and compared exactly.

## Upgrading

Nothing breaks. On the first `load context` after you copy the new `AGENTS.md`, the AI checks the headers. If it reports a mismatch, say `"repair state files"` once. The repair rewrites only the header block and the daily title date; it does not touch the body or earlier checkpoints.

The new `AGENTS.md` and the common policy are the only files you copy. Existing projects keep their history; only the header of the current state files and today's checkpoint change. The header check is built into the existing validator; there is no new script.
