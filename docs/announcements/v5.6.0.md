# Simple AI Workflow v5.6.0

Released 2026-11-03.

## One delivery flow, two procedures

Work now runs through two procedures.

- `PROCEDURE MANAGE-ISSUES` files, lists, closes, or reopens a ticket, and writes and reviews a plan when you ask. A ticket-only request stops at the ticket.
- `PROCEDURE IMPLEMENT-PLAN` delivers an approved plan: branch, build, review, checkpoint, commit, and ship.

The order lives in one place. The common policy keeps the invariants, and the issue template, workflow guide, README, and collaboration guide point to the procedures instead of restating them.

## Merge modes

A new optional section in `ai-customization.md`:

```markdown
## Merge Policy
**Merge Mode**: auto
```

- `direct`: squash-merge locally, delete the branch, push the trunk. For solo work.
- `pr`: push the branch and open a pull request or merge request, or hand you the URL. For team work.
- `auto`: behaves as `direct` and falls back to `pr` when a direct push is rejected.

No `gh` or `glab` is required. Without a CLI, the AI pushes the branch and gives you the create or compare URL.

## Tickets

A ticket is a local file by default, or an external issue when you supply one. A local ticket closes in the branch commit. An external ticket closes when the merge lands. No repository change happens after the merge.

## Upgrade

1. Pull the latest workflow and run the sync script as usual. It adds the `## Merge Policy` section if your customization file does not have it.
2. Set `**Merge Mode**: pr` in a team repository that requires a pull request. Leave it `auto` or `direct` for solo work.
3. The working phrases are `"file an issue"`, `"plan the issue"`, and `"implement the plan"`. Each one stops when its action is done.
