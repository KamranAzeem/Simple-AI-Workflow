# Simple AI Workflow v5.5.2

Released 2026-11-03.

## Policy loads now find the right file

A policy step used to say `ai/policies/ai-policy-...md`. In your project, `ai/policies/` is your own custom-policies directory. The policy files live in your Simple-AI-Workflow clone. So the instruction pointed at the wrong tree, and the load failed with "no such file".

This release removes the hardcoded paths.

## What changed

- A policy file is named without a directory and resolved from the Global AI Policies Directory.
- The resolution rule is stated once in `AGENTS.md` and mirrored in the common policy.
- The peer review, codebase examination, design docs, and design docs migration steps now name the policy and the directory anchor.
- The bootstrap template, the decision store, the clone suggestion, and the manual settings instruction now use the workflow, home, and settings anchors.
- The meta policy states once that its `support-files/` and `design-docs/protocol-decisions.md` paths resolve from the Global AI Workflow Directory and exist only in the protocol repository.
- The reference test gains a path-conformance check, so a hardcoded policy path fails the test.

User-facing docs are unchanged. They describe the clone layout, where `ai/policies/` is correct.

## Upgrade

1. Pull the latest workflow and run the sync script as usual.
2. Run the reference test if you want to confirm: `bash support-files/test-protocol-references.sh`.
3. Nothing else changes. There are no new commands and no new scripts.
