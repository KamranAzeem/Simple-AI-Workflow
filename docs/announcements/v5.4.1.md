# Simple AI Workflow v5.4.1

Released 2026-10-29.

## A correction to the knowledge-file standard

The v5.4.0 limits didn't work out. It measured knowledge files in lines and told the repair to split a file that covered too much. This release fixes that.

Knowledge files now use size, not lines. Use 10 KB as a soft target; never let it override completeness. When a file passes 15 KB, the repair cleans it up automatically. There's no line target anymore.

Files never split. When a file mixes topics, the repair merges duplicates and trims what doesn't belong, and the file count can't grow. A checklist stays one file, even when it's long. A file that is still over 15 KB after cleanup stays one file and gets reported. A mixed file is a little harder to spot in the name index; that's the trade-off we accept.

Every knowledge file stands on its own. It starts with this header:

> **Knowledge file.** This file stands on its own. Keep the facts, rules, reasons, and checks that belong to it; remove bookkeeping and duplicates. Run `repair knowledge files` when it passes 15 KB.

Keep the facts, rules, reasons, and checks the file needs, and don't point at another file. A domain command, a system path, or a path a checklist step writes or edits is content, not a pointer.

## The repair asks no questions

`"repair knowledge files"` is the approval. The repair backs up the old files, preserves anything ambiguous, and reports what it merged, trimmed, or left alone. It doesn't stop to ask you along the way. `dry run` still works if you want to see the plan first.

A project knowledge file may keep identifying names. A global knowledge file removes them. Raw secrets are banned in both.

## Upgrade

1. Pull the latest workflow and run the sync script as usual.
2. Run `"repair knowledge files"` once in each project. It takes a while on a real knowledge base, so let it finish. It's how your files get fixed.
3. Add `global` if you keep global knowledge.

Nothing breaks while you wait. The checkpoint flags the problems but doesn't edit your files.
