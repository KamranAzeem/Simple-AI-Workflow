# Simple-AI-Workflow v4.0.0

Released 2026-10-06.

Nothing about how the workflow works has changed. This release gives proper names to the background parts. You keep using the same phrases you always used, like "load context", "checkpoint", "peer review", and "backup ai".

## What actually changed

Until now, the procedures were named with single letters (Procedure A, Procedure B, and so on), the steps were numbered ("Step 5"), and the tiers were numbered too. That works only as long as nobody reorders anything. The moment a procedure moves, every reference to it can point to the wrong place. So in v4.0.0 all of them have clear names that never change.

- Procedures: LOAD-CONTEXT, WRITE-CHECKPOINT, RUN-PEER-REVIEW, POST-COMPACTION-RECOVERY, CREATE-BACKUP, EXAMINE-CODEBASE, MANAGE-ISSUES, REPAIR-STATE-FILES, BOOTSTRAP-PROJECT.
- Steps and sub-steps: names like STEP PROOF-OF-LOAD and STEP ATOMIC-WRITE.
- Tiers: TIER CONFIGURATION, TIER READ-FIRST-RULES, TIER TRIGGERED-PROCEDURES, TIER APPENDIX.
- Report items: names like ITEM STATE-FILE-HEALTH, instead of "bullet (d)".

## Are you safe?

If you never used the old letters anywhere in your own notes, your custom policies, or your ai-customization.md, you are safe. Just pull the latest and carry on.

This release did not rewrite history, so a normal `git pull` is enough. The 2026-09-22 release was the one that needed a hard reset. This one does not.

## If you did use the old letters

Some of you may have written "Procedure D", "Procedure E", or "Step 5" in your own notes, custom policies, or in ai-customization.md. Those references still mean something to you, but they no longer match the headings and filenames in the protocol. Two things to do.

1. Open the migration map in the Simple-AI-Workflow repository you cloned (your Global AI Workflow Directory) at `ai/shared/project-knowledge/protocol-name-migration-map-2026-10-06.md`. It lists every old name and its new name side by side.
2. Check your `ai-customization.md`. If it names a procedure with a letter, update it. The common one is "Procedure D", which is now PROCEDURE RUN-PEER-REVIEW.

You can let your AI do this for you. Paste this instruction into your chat:

"Read the migration map in the Simple-AI-Workflow repo (my Global AI Workflow Directory) at ai/shared/project-knowledge/protocol-name-migration-map-2026-10-06.md, then update my ai-customization.md so that every old procedure letter or step number is replaced with its new canonical name. Show me the diff before you write anything."

## A word of comfort

The functionality has not changed at all. Every procedure does exactly what it did before. The new names are only for the background plumbing, and each procedure also keeps a list of aliases, so plain phrases like "post-compaction recovery" and "checkpoint" still trigger the same behaviour. If you use the built-in trigger phrases, you will not notice any difference.

The full release notes are in the [v4.0.0 release](https://github.com/KamranAzeem/Simple-AI-Workflow/releases/tag/v4.0.0).
