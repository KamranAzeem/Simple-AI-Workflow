# Simple AI Workflow v6.7.0

Released 2026-11-19.

## The AI now has a tool order

The protocol told the AI to read git-ignored protocol files with the shell. That fought the built-in-tools-first rule, and it pushed the AI to the shell for things the editor tools do better.

I added `## Tool Selection` to the common policy. It is a short ladder:

1. Use a purpose-built tool when it directly performs the operation.
2. Use the shell for a command or file operation that no purpose-built tool covers, including git, validators, directory creation, archives, permissions, and paths outside the tool's reach.
3. Use Python or another runtime only when neither can do the job, and say why.

The AI reports every fallback and names the tool. It never uses a lower rung to skip an approval or a rule.

## Readable protocol files

The old `Surgical Git-Ignore Exception` is gone. The new rule is `Git-Ignored Protocol Files Are Readable`: try the built-in file read first; if the harness refuses or hides the path, use the shell and report the fallback. It never refuses a protocol file just because git ignores it.

## What did not change

- The shell preference is still separate. That work stays with GitHub #9 and the `Default Shell Interpreter` configuration.
- There is no session-start tool inventory.
- Approvals, safety checks, and protocol rules still bind at every rung.

## The guard

`tests/test-tool-selection.sh` checks the ladder, the readable rule, the removed old rules, and the validator anchors. The validator fails if the mandatory shell-read sentence or the old file-edit rule comes back. The suite is 22 scripts.
