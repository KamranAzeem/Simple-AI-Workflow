# Simple AI Workflow v5.5.0

Released 2026-10-31.

## A work item now has a real finish line

A plan could stop at "implemented and verified" and still leave the ticket open. The plan ended with a request for merge approval, so the commit, the ticket close, and the checkpoint never ran. Nothing checked the plan against the procedure.

This release fixes the gap.

## What changed

Every plan now carries a close sequence. It binds each close action to a repo, branch, base ref, artifact, and evidence. A plan whose last action is "request merge approval" is incomplete.

Plan review checks the close sequence. It returns `CHANGES REQUESTED` when a close action is missing, has no owner, or has no evidence. A missing step now fails at plan review, not at merge time.

Before any close or merge claim, the AI checks each repo. The branch must be at least one commit ahead of its resolved base, and the working tree must be clean. A branch with no commits cannot be called reviewed, closed, or ready. The base ref comes from the plan, not from a hardcoded branch name.

Approving a feature branch now covers commits and pushes on that branch. The trunk merge, tag, release, and external system writes still need your approval.

An uncommitted branch is recorded as unfinished work, never as "merge pending". The pending item names the next step that needs no approval.

All AI state and checkpoints live under the project root `ai/`, whether or not it is a git repository. In a multi-repo project, the project root repo owns the state, and a checkpoint never goes into a secondary repo.

## Upgrade

1. Pull the latest workflow and run the sync script as usual.
2. Nothing else changes. There are no new commands and no new scripts.
3. Open tickets keep working. The stricter plan shape applies to plans written after the upgrade.
