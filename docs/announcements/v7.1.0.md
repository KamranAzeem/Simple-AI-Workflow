# v7.1.0

This minor release adds an optional shared team knowledge store. A team can pool the lessons it keeps relearning, without copying anyone's private project state.

- Two optional keys in `## AI Workflow Configuration`: `Team AI Knowledge Directory` for the local clone or mount, and `Team AI Knowledge Repository` for the publish remote.
- The boot indexes `lessons/` by filename only. An unconfigured project behaves exactly as today; a missing path reports `[PENDING]` and the load continues.
- Say `"update team knowledge"` or `"publish to team knowledge"` to contribute one lesson. The AI states Class A (internal or same audience), removes secrets, checks for an exact hash duplicate, and opens a pull request. It never merges.
- Team lessons keep names and infrastructure detail and never keep secrets. The local sensitive-names list stays local; repository access is the privacy control.
- Precedence is project knowledge, then team knowledge, then personal global knowledge.
- The team policy is procedure-loaded and loads at boot only when the store is configured.
- New `ai-policy-team-knowledge.md` brings the policy count to 25, and `knowledge-publish.md` brings the procedure count to 16. The validator floor is 25, and the index reports 53 triggers.
- `tests/test-team-knowledge.sh` and a two-lesson fixture pin the shapes and the wiring.
- Upgrade: pull the clone and run the sync script to pick up the new `AGENTS.md` anchors. No repair is needed. The store stays unconfigured until you add the keys.
