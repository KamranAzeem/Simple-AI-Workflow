# Simple-AI-Workflow v5.2.0

This release gives the AI a general coding standard, so the code it writes follows the same quality bar whether you ask for a script, a service, or a module.

## What changed

Until now, the AI had no general coding standard. It followed the domain policy for the task, and for a script, a CLI, or a mixed repository there was no standard at all.

The new `coding-baseline` policy fills that gap. Add it to your Active Expertise:

```markdown
## Active Expertise

- coding-baseline
```

The AI then applies industry-recognized practices to new and changed code:

- Clean Code: meaningful names, one job per function, comments that explain why, and explicit error handling.
- SOLID, DRY, YAGNI, and Twelve-Factor.
- TDD.
- OWASP secure coding.
- Resilience patterns: timeouts, bounded retries, and idempotency.
- Telemetry.

Telemetry is on by default for production code. The AI classifies the work, tells you what it recommends, and proceeds unless you decline. Tests, examples, exercises, and one-off scripts stay telemetry-free by default.

The policy keeps the no-disturbance rule: new code follows the policy, and existing code changes only inside the requested scope. It does not rewrite or reformat code you did not ask about.

## Upgrading

Nothing breaks if you do nothing. The policy is opt-in and additive. Enable `coding-baseline` when you want the general coding standard in a project.
