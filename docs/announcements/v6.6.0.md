# Simple AI Workflow v6.6.0

Released 2026-11-18.

## Plug-in policies

The common policy now holds always-on invariants only. The task-specific rules moved to standalone policies that load when the task needs them: outbound content scrub, knowledge, issue management, design documents, and thinking modes. The state-file rules and the universal engineering and testing standards stay in the common policy, because every session needs them.

The one-way boundary is the rule: a plug-in may cite the common policy, and the common policy names no plug-in.

## Policy loading declaration

A policy may declare when it loads in an optional `## Loading` section, with one path per policy: `boot`, `trigger`, `procedure`, or `expertise`. A policy with no declaration keeps its current behavior. Project policies keep the legacy boot load, so no project needs a change. A procedure may still load a policy by name.

The authoring validator and `tests/test-policy-load-paths.sh` check that every declared path is real, so a procedure that names a missing policy fails the suite.

## Custom policies

The new [custom policy howto](../custom-policy-howto.md) covers the file shape, the four loading modes, validation, and migration. Put a custom policy in the project root `ai/policies/`, give it the standard shape, and validate it with the clone's validator.

## Legacy policies

Linux, accounting, career coaching, Windows system administration, and academic research are rewritten to the authoring standard: one sentence per rule, flat bullets, a declared loading mode. Their rules are unchanged.

## Verification

The protocol validator passes 8/8, the authoring validator passes, and all 19 test scripts pass. The suite now includes load-path, policy-shape, project-scope index, and trigger-namespace checks.

## Known gap

The common policy prose is still denser than the authoring standard. The structural validator passes, and the prose rewrite is a separate follow-up unit.

## Upgrade

Pull the workflow, run the sync script, and restart the session. Project policy behavior is unchanged, so no repair is needed.
