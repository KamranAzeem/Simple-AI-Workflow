# Simple AI Workflow v6.6.2

Released 2026-11-18.

## A label on every policy

Here is the problem I wanted to fix. A policy file could sit in the `ai/policies/` folder and nothing would load it. The index would still list it, and you would not see the difference.

The index had a word for this: `legacy`. All it means is "this file has no label that says how it loads". Thirteen of the 23 policies had that word.

So I added the label to 12 of them. The thirteenth is the common policy, and I will explain why it stays as it is.

## The three ways a policy loads

A policy loads in one of three ways:

1. You say a phrase, and the AI loads it. For example, "cloud standards" loads the cloud policy. The label is `trigger`.
2. A procedure reads it while the procedure runs. For example, the peer review procedure reads the code review policy. The label is `procedure`, and the file also names the procedure.
3. Your `ai-customization.md` lists it under Active Expertise. For example, `web-frontend` loads the web frontend policy. The label is `expertise`.

Twelve files now carry the right label:

- `api-backend`, `cloud`, `data`, `dba`: `trigger`.
- `code-review`, `codebase-examination`, `handoff`: `procedure`.
- `coding-baseline`, `mobile-apps`, `observability`, `web-frontend`, `meta`: `expertise`.

The common policy is the exception. It is read at the start of every session, before the AI looks at any other policy. It has no phrase, procedure, or expertise name to point at, so it keeps `legacy`.

## What the labels catch

Before, a broken policy could look fine. Now the checks catch it:

- If a `trigger` policy has no phrase, the test fails.
- If a `procedure` policy names a procedure that does not exist, the test fails.
- If a `procedure` or `expertise` policy also has a phrase, the test fails.

Rename `run-peer-review`, and the code review policy fails the test the next time you run it. That is the part that was missing.

## What did not change

No rule changed. I added 4 or 5 lines to each file. The policy count is still 23 and the trigger count is still 47.

## Quick check

Run `bash tests/run-all.sh`. It now checks one policy of each kind: `cloud` for trigger, `code-review` for procedure, `web-frontend` for expertise, and `common` for legacy.

## Upgrade

Pull the workflow, run the sync script, and restart the session. Nothing else changes, and the rest of the protocol behaves exactly as before.
