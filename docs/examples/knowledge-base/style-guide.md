# Project Style Guide

## Context

This sample project defines the tone and format for its documentation and chat output.

## Rule or Fix

- Use a professional, direct, and concise tone.
- Write in English.
- Format output as GitHub-flavored Markdown.
- Keep output lean.
- Minimize conversational filler.
- Prioritize technical rationale.

## Why

- A direct tone respects the reader's time.
- A lean output keeps the technical point visible.
- A consistent format is easier to scan.

## Verify

- Confirm the output is direct and free of filler.
- Confirm the Markdown renders as GitHub-flavored Markdown.
- Confirm the technical rationale is present.
