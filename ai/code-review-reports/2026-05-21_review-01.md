## Critical

- [ ] `AGENTS.md` — **PROCEDURE D is placed in TIER 5 (Appendix) instead of TIER 3 (Triggered Procedures).**
  Procedures A, B, and C are all inside TIER 3. An AI agent scanning TIER 3 for triggered procedures will never reach TIER 5 and will not find Procedure D. This defeats the entire feature for weak models — the exact audience it is designed for. PROCEDURE D must be moved to TIER 3, immediately after PROCEDURE C.

## Major

- [ ] `support-files/validate-protocol.sh:107-113` — **`VALIDATION_TEST.md` is not cleaned up if the script exits after creating it but before the cleanup block.**
  `set -e` causes an immediate exit on any error between `touch ai/daily-checkpoints/VALIDATION_TEST.md` and `rm ai/daily-checkpoints/VALIDATION_TEST.md`. The stale test file then persists in `ai/daily-checkpoints/`, polluting the checkpoint history and potentially confusing future context loads. Fix: add `trap 'rm -f ai/daily-checkpoints/VALIDATION_TEST.md' EXIT` before the `touch` command.

- [ ] `README.md` — **Three corrupted/duplicate lines at the end of the Docs and Slides section.**
  The file ends with:
  ```
  - Mobile app development policy guide: `docs/ai-policy-mobile-apps-guide.md`
  ent policy guide: `docs/ai-policy-mobile-apps-guide.md`
  pps-guide.md`
  ent policy guide: `docs/ai-policy-mobile-apps-guide.md`
  ```
  The last three lines are corrupted copy/paste artifacts. They render as broken text in any Markdown viewer and in the GitHub README. Remove the three trailing corrupt lines.

- [ ] `support-files/sync-agents-md.ps1:6` — **SYNOPSIS shows `-Root` but the actual parameter is `-TargetPath`.**
  ```
  ./sync-agents-md.ps1 -Source ../AGENTS.md -Root C:\Projects -WhatIf
  ```
  The `param()` block defines `$TargetPath`, not `$Root`. A user following the help text will get a PowerShell error. Update SYNOPSIS to use `-TargetPath`.

## Minor

- [ ] `support-files/validate-protocol.sh:71` — **Step 6 echo says "10 modular policies"; there are now 11.**
  `ai-policy-code-review.md` was added this session. The echo string `"[6/9] Verifying policy baseline (10 modular policies)..."` is stale. Update to "(11 modular policies)" or change to a dynamic count.

- [ ] `support-files/sync-agents-md.sh:103` — **`IFS=$'\n'` is set at the global scope and never unset.**
  Setting `IFS` globally changes word-splitting behaviour for all subsequent shell operations. Scope it with `( IFS=$'\n'; ... )` or unset/restore it after the `while read` loop completes. On some shells this causes subtle bugs with space-containing paths in later code.

- [ ] `README.md:118` — **`AGENTS.md (Canonical)` in the ASCII diagram — project convention requires "primary", not "canonical".**
  Per the established naming convention for this project, "canonical" should be replaced with "primary". This is in the ASCII diagram: `├─ AGENTS.md (Canonical)`.

- [ ] `support-files/validate-protocol.sh:13-19` — **Hardening check verifies Procedure A anchor but not Procedure D.**
  The validation script checks that `PROCEDURE A` exists in `AGENTS.md` but has no corresponding check for the newly added `PROCEDURE D`. After the critical fix moving PROCEDURE D to TIER 3, a verification anchor check should be added here to prevent future regressions.

- `support-files/validate-protocol.sh` — Add `trap 'rm -f ai/daily-checkpoints/VALIDATION_TEST.md' EXIT` before the `touch` command. This guarantees cleanup regardless of where the script exits, without requiring a separate cleanup path.

- `support-files/sync-agents-md.sh` — Add `[ -d "$TARGET_PATH" ] || { echo "TARGET_PATH is not a directory: $TARGET_PATH" >&2; exit 2; }` after argument parsing. The current code passes a non-directory to `find` silently and reports "0 matches found" — not obvious enough for an operator error.

- `support-files/validate-protocol.sh` — Consider incrementing the check count from `[X/9]` to `[X/10]` when the Procedure D anchor check is added, to keep the progress labels accurate.
