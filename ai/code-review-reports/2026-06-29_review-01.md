## Minor

- [ ] `AGENTS.md` — Procedure A Step 4 sub-bullet + Step 7 bullet (f): "date of the most recent entry" is ambiguous for `next-steps.md` and `context.md`. Neither file contains a standalone date field — the date is embedded in the checkpoint ID format `CP-YYYY-MM-DD-NN`. The instruction implies a plain date but requires silent extraction from the ID. An AI may implement this inconsistently: one might report `CP-2026-06-22-04`, another `2026-06-22`. The wording should specify: *"the date of the most recent entry (for checkpoint-ID-based files, extract the date from the `CP-YYYY-MM-DD-NN` identifier)"* — or unify both files under "checkpoint ID and date" instead of "date" alone.

- [ ] `AGENTS.md` — Procedure C Step 1, `Fresh-Read Before Write`: "Do not write from a cached or summarised version held in context" — "context" is ambiguous. In this protocol's vocabulary, `context` frequently refers to `context.md` (the state file). An AI could read this as "don't use `context.md` as the source before writing" rather than the intended meaning: "don't use the conversation context window / active memory." Should say "held in the active context window" or "held in conversation memory" to disambiguate.
