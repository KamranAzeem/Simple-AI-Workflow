## Minor

- [ ] `support-files/sync-agents-md.ps1:70-73` — **Dead-code fallback for `$targetUserDir` uses the same regex as the primary match; it can never succeed when the primary failed.**
  ```powershell
  # Primary
  $targetUserDir = if ($targetContent -match '\*\*Global User AI Directory\*\*: `([^`]+)`') { $Matches[1] } else { $null }
  # Fallback — identical pattern, unreachable
  if (-not $targetUserDir -and ($targetContent -match '\*\*Global User AI Directory\*\*: `([^`]+)`')) {
     $targetUserDir = $Matches[1]
  }
  ```
  The `$targetWfDir` fallback correctly uses an *older* pattern (`Global Policies Directory`) — the `$targetUserDir` fallback was likely copied from it but the old-pattern equivalent was never substituted. The fallback should either use the legacy naming for User AI Dir (if one exists) or be removed.

- [ ] `support-files/sync-agents-md.ps1:99` — **`Set-Content -Encoding UTF8` in Windows PowerShell 5.1 writes UTF-8 *with* BOM. AGENTS.md is BOM-less. Synced copies written on PS 5.1 will have a BOM prepended.**
  The README upgrade instructions invoke `powershell` (not `pwsh`), which means PS 5.1 on Windows. The BOM will appear as a stray `ï»¿` character in any tool that reads the file as raw bytes, and can break `grep` anchors and `head -n 1` metadata checks. Fix:
  ```powershell
  [System.IO.File]::WriteAllText($target, $newContent, [System.Text.UTF8Encoding]::new($false))
  ```
